현재 워크트리(스테이징/언스테이징/untracked 포함)의 변경 사항을 검토해 논리적 단위로 나눠 커밋하고, 바로 푸시까지 한다.

인자: (선택) 커밋 범위 힌트. 없으면 `git status`의 모든 변경을 대상으로 한다.

## test-commit과의 차이

- `test-commit`은 Playwright E2E까지 돌리고 **푸시는 하지 않는다**.
- 이 명령은 정적 검증(tsc/lint)까지만 하고 **바로 push까지** 수행한다. 사용자가 직접 브라우저로 확인 중이거나("1차 검수는 내가 한다"), 별도로 e2e를 나중에 몰아 돌릴 계획일 때 쓰는 가벼운 경로다.
- E2E/브라우저 검증이 필요한 상황이면 이 명령 대신 `test-commit`을 쓰거나, 사용자에게 먼저 확인한다.

## 전제

이 명령은 대화 맥락 없이 콜드로 호출되는 경우가 많다 — 다른 세션이나 Codex 등 별도 에이전트가 작업해놓은 결과를 대신 커밋·푸시해주는 용도이기 때문이다. "누가 왜 이 변경을 했는지"는 알 수 없고 알 필요도 없다. **판단 근거는 오직 `git status`/`git diff`/`git log`뿐**이며, 무엇을 커밋할지는 지금 워크트리에 있는 변경 전체를 그대로 범위로 삼는다(인자로 힌트가 있으면 그것도 참고).

## 핵심 정책

1. **워크트리에 있는 변경 전체를 범위로 삼는다.** 별도 대화 맥락과 대조하지 않는다 — 다만 diff 자체를 봤을 때 이상해 보이는 것(설명 없이 섞인 것 같은 대규모/무관한 변경, `.env`나 credential류처럼 민감정보로 보이는 파일, 명백한 디버그 코드)이 있으면 멈추고 사용자에게 확인한다.
2. **논리적 관심사 단위로 커밋을 나눈다.** 같은 기능/화면을 건드리는 변경은 한 커밋으로 묶고, 서로 무관한 변경(예: SEO 정적화 vs 홈 위젯 리디자인)은 별도 커밋으로 분리한다. 전부 한 가지 관심사면 커밋 1개로 충분하다.
3. **정적 검증만 기본으로 한다.** `pnpm build`, `.next` 캐시 삭제, dev 서버 재시작은 하지 않는다(CLAUDE.md 개발 서버 규칙). E2E·크롬 브라우저 테스트는 사용자가 명시적으로 요청하지 않는 한 생략한다.
4. **신규 오류만 고친다.** tsc/lint에서 이번 변경으로 새로 생긴 오류만 대응하고, 기존부터 있던 오류는 건드리지 않는다.
5. **현재 브랜치가 main이면 push 전에 먼저 확인한다.** feature 브랜치(main이 아닌 브랜치)면 바로 push해도 된다 — 반복적으로 이렇게 진행해온 패턴.
6. **Claude 저작자 표시를 항상 포함한다.** 커밋 메시지 끝에 `Co-Authored-By`와 `Claude-Session` 줄(현재 세션 시스템 지침에 명시된 값)을 그대로 붙인다.

## 절차

### 1단계 — 변경 파악 및 분할 계획
- `git status`와 `git diff`(untracked는 내용도 확인)로 전체 변경을 읽는다.
- 관심사별로 묶어 커밋 개수와 각 커밋에 포함할 파일을 정한다.

### 2단계 — 정적 검증 (CLAUDE.md 작업 검증 규칙)
```
npx tsc --noEmit -p .
pnpm lint   # 또는 npx eslint <변경 파일들>
```
- 신규 오류가 있으면 고치고 재검증. 못 고치면 중단하고 보고한다.

### 3단계 — 커밋
- 계획한 단위대로 `git add <파일들>` → `git commit`을 반복한다.
- 커밋 메시지는 한국어, `feat:`/`fix:`/`chore:` 프리픽스, "무엇을 왜 바꿨는지" 위주로 작성한다. 최근 `git log --oneline`으로 톤을 맞춘다.
- 메시지 끝에 Claude 저작자 표시를 붙인다.

### 4단계 — 푸시
- 현재 브랜치가 main이 아니면 `git push origin <현재 브랜치>`를 바로 실행한다.
- main이면 push 전에 사용자에게 확인한다.

### 5단계 — 결과 보고
- 만든 커밋 목록(`git log --oneline -N`)
- tsc/lint 결과 한 줄 요약
- push 결과
- 커밋하지 않고 남겨둔 변경이 있으면 그 이유

## 출력 형식

- 분할 계획(커밋 # · 파일 · 메시지 요지)
- 정적 검증 결과
- 최종 커밋 로그 + push 결과
